Course Summaries and Key Points

Outlines, objectives and lesson counts come from each course page. The "Key points to remember" bullets are condensed exam-oriented takeaways based on those syllabi plus standard Claude API / Claude Code / MCP practice; lesson videos are not public, so verify details in the courses.
AI Fluency: Framework & Foundations

14 lectures, 1.1 h video, 1 quiz, certificate. By Anthropic with Prof. Rick Dakan (Ringling College) and Prof. Joseph Feller (UCC).

Outline

  • AI Fundamentals & Framework (10 lessons): how generative AI works, capabilities and limits, why AI fluency matters, intro to the 4D Framework.
  • Practical AI Skills (10 lessons): project planning with AI, prompting, evaluating output, the description-discernment loop.

Key points to remember

  • The 4Ds: Delegation (what to hand to AI vs. keep), Description (communicate goals, context, and format clearly), Discernment (critically evaluate outputs and process), Diligence (responsible, transparent, accountable use).
  • Three modes of interaction: automation, augmentation, agency.
  • Description and Discernment form an iterative loop: prompt, assess, refine.
  • Goal is effective, efficient, ethical, and safe collaboration, beyond "cool prompts"; applies regardless of which model or tool emerges.
  • Disclose AI involvement and keep humans accountable for final output (the course itself includes an AI diligence statement).
Claude 101

Free, certificate of completion.

Outline

  • Meet Claude: what Claude is, first conversation, getting better results, desktop usage.
  • Organizing work and knowledge: Projects, Artifacts, Skills.
  • Expanding Claude's reach: connecting tools, enterprise search, Research for deep dives.
  • Putting it together: use-cases by role, other ways to work with Claude, next steps.

Key points to remember

  • Projects hold persistent context and files for related work.
  • Artifacts are standalone outputs (documents, code, apps) created alongside the chat.
  • Skills package repeatable instructions; connectors link Claude to external tools and data.
  • Better results come from clear context, goals, and iteration.
Building with the Claude API

84 lectures, 8.1 h video, 10 quizzes, certificate. Prereqs: Python, JSON, API key.

Outline (lessons per section)

  • Getting started with Claude (16): authentication, requests, multi-turn conversation, system prompts, streaming, structured output.
  • Prompt engineering & evaluation (16): prompting strategies, automated eval pipelines.
  • Tool use with Claude (14): function calling, multi-turn tool loops, batch tool calls, built-in tools.
  • Retrieval augmented generation (10): chunking, embeddings, BM25 hybrid search, multi-index, reranking, contextual retrieval.
  • Model Context Protocol (12): custom tools and resources, servers, clients, integration lifecycle.
  • Claude Code & Computer Use (8).
  • Agents and workflows (11): parallelization, chaining, routing, debugging.

Key points to remember

  • The API is stateless: send the full message history on each request.
  • Tool loop: Claude returns tool_use; you run the tool and return a tool_result; repeat until end_turn.
  • Use system prompts for role/behavior; prefill and stop sequences to shape structured output.
  • Evaluate prompts systematically: test dataset, grader (code-based or model-based), score, iterate.
  • Prompting techniques: be clear and direct, use examples (multishot), XML tags, specify output format.
  • RAG: chunk, embed, retrieve; hybrid search combines semantic and BM25; rerank results; contextual retrieval adds chunk context before embedding.
  • Workflows (predefined steps: chaining, routing, parallelization) are more predictable; agents are flexible but less predictable. Prefer workflows when steps are known.
  • Features to know: streaming, prompt caching, extended thinking, citations, image/PDF input.
Introduction to Model Context Protocol

16 lectures, 1 h video, 1 quiz, certificate. Prereqs: Python, async/await. Hands-on project: a document management system.

Outline

  • MCP fundamentals & server development (8): architecture, why MCP exists, building a server with tools using the Python SDK, testing with the MCP Inspector.
  • Client implementation & advanced features (8): building clients, session management, resources, prompts, full application flow.

Key points to remember

  • MCP removes the need to hand-write tool schemas and integrations for each external service.
  • Client-server model: your app hosts an MCP client that talks to one or more MCP servers.
  • Control patterns: tools are model-controlled, resources are app-controlled data, prompts are user-controlled templates.
  • Test and debug servers with the MCP Inspector.
  • Handle async communication and resource cleanup correctly in clients.
Claude Code in Action

9 lectures, certificate. For developers already using Claude Code for single prompts who want longer, less supervised, team-wide workflows.

Outline

  • Steer the Work (1): plan mode, directed compaction, rewind menu, hands-on vs. autonomous goal / loop runs.
  • Configure Claude (4): lean CLAUDE.md, skills, permission modes, hooks.
  • Automate Repeat Work (2): scheduled routines, headless mode, managed code review and GitHub action in PRs.
  • Verify and Share (2): proportional verification, test-gated hooks, packaging a setup as a plugin.

Key points to remember

  • Scope with plan mode first; compact deliberately so summaries keep what matters; rewind to course-correct.
  • Run parallel agents safely with git worktrees.
  • Three instruction surfaces: put each rule where it belongs. Keep CLAUDE.md short so Claude actually follows it.
  • Skills package repeated procedures; start with a verification skill that checks Claude's work.
  • Match permission mode to the job: hands-on review through unattended pipelines.
  • Hooks enforce unskippable rules deterministically, using permission-decision JSON and exit codes to control the loop.
  • Headless jobs use structured output for your own pipelines; routines run scheduled prompts on Anthropic infrastructure.
  • Verify unsupervised runs in proportion to how little you watched; gate turns on real test results; share trusted setups as a plugin.

Claude on Google Cloud

85 lectures, 8 h video, 10 quizzes, certificate. Prereqs: Python, JSON, Google Cloud account with Vertex AI access.

Outline

  • Getting started (16), Prompt engineering & evaluation (16), Tool use (14), RAG (10), MCP (12), Claude Code & Computer Use (8), Agents and workflows (11).

Key points to remember

  • Set up and authenticate Claude through Vertex AI using the Anthropic SDK.
  • Pick models by the trade-off among intelligence, speed, and cost.
  • Evaluate prompts with objective scoring metrics.
  • Tools: web search, file operations, custom functions; advanced features: extended thinking, citations, prompt caching.
  • Design workflows for known task sequences and agents for flexible problem-solving.

Cross-course themes

  • Prefer deterministic mechanisms (hooks, schemas, code checks) over prompt-only rules when compliance matters.
  • Start with simple workflows; use agents only when flexibility is needed.
  • Measure prompts with evals instead of guessing.
  • Verify AI work in proportion to how little you supervised it.
  • Bedrock, Vertex AI, and the direct API share the same concepts; only authentication and client setup differ.

Key Concepts (self-test flashcards)

How does an agentic loop terminate?

When stop_reason is end_turn. If it is tool_use, execute the tools, append tool_result blocks, and call the model again. Do not parse natural-language text to decide completion.

Prompt instruction vs. hook: which for a hard business rule?

A hook (programmatic enforcement) gives deterministic compliance. Prompts are probabilistic, so use them for guidance, not for rules with financial or safety consequences.

Do subagents inherit the coordinator's conversation history?

No. They run with isolated context, so the coordinator must pass all required findings and instructions in the task prompt.

Best way to get reliably structured JSON?

Define a tool with a JSON schema and force it with tool_choice. This prevents syntax errors, but semantic errors still need validation and retry.

When is the Message Batches API appropriate?

Latency-tolerant, high-volume work (e.g., overnight reports) for a cost saving. Not for blocking workflows such as pre-merge checks.

Where do team-shared Claude Code instructions live?

Project-level CLAUDE.md (or .claude/ rules) committed to version control. User-level files are personal and not shared.

Why limit tools per agent?

Too many tools degrade selection accuracy. Give each agent a focused set scoped to its role.

Three MCP primitives?

Tools (model-controlled actions), resources (application-controlled data), prompts (user-controlled templates).
